# 任务自动转交配置说明

## 功能概述

任务自动转交功能允许配置任务完成后的自动转交规则，实现工作流的自动化流转。

**示例场景**：张三完成工作A后，系统自动创建并分配给李四的工作B。

## 配置方式

### 1. 访问配置页面

在Django后台管理中，访问：**生产管理 → 任务自动转交配置**

### 2. 创建转交规则

点击"添加任务自动转交配置"，填写以下信息：

- **源任务类型**：选择完成后需要触发转交的任务类型
- **目标任务类型**：选择源任务完成后自动创建的任务类型
- **执行条件**：
  - `总是执行`：无论任务完成状态如何都执行
  - `仅成功时执行`：只有任务成功完成时才执行
  - `仅失败时执行`：只有任务失败时才执行
- **是否启用**：可以临时禁用规则而不删除
- **执行顺序**：当同一源任务有多个转交目标时，按此顺序执行
- **延迟执行（小时）**：源任务完成后延迟多少小时再创建目标任务（0表示立即执行）
- **配置说明**：描述此转交规则的业务场景和用途

### 3. 配置验证

系统会自动进行以下验证：

1. **相同任务检查**：源任务和目标任务不能相同
2. **循环依赖检测**：自动检测是否存在循环依赖（A→B→C→A）
3. **唯一性检查**：同一源任务、目标任务、执行条件的组合不能重复

### 4. 工作流预览

在配置详情页可以预览：
- 工作流路径：显示从源任务到目标任务的完整转交路径
- 循环依赖检查：实时检查是否存在循环依赖

## 批量操作

在配置列表页，可以执行以下批量操作：

- **启用选中的转交规则**：批量启用配置
- **禁用选中的转交规则**：批量禁用配置
- **验证选中的配置**：批量验证配置的有效性

## 数据迁移

### 初始化现有配置

系统提供了数据初始化命令，可以将硬编码的配置迁移到数据库：

```bash
# 预览模式（不实际创建）
python manage.py init_task_transfer_configs --dry-run

# 实际创建配置
python manage.py init_task_transfer_configs

# 覆盖已存在的配置
python manage.py init_task_transfer_configs --overwrite
```

### 数据库迁移

首次使用需要执行数据库迁移：

```bash
python manage.py migrate production_management
```

## 工作原理

1. **任务完成触发**：当任务状态变更为"已完成"时，系统会调用 `_handle_task_followups` 函数

2. **配置读取**：
   - 优先从数据库读取启用的转交配置
   - 如果没有数据库配置，则使用硬编码的 `TASK_COMPLETION_FOLLOWUPS` 作为后备（向后兼容）

3. **任务创建**：
   - 按配置的执行顺序依次创建目标任务
   - 自动分配任务给对应角色的人员
   - 在任务的 metadata 中记录转交来源信息

4. **延迟执行**：
   - 当前版本：延迟执行功能已预留接口，但暂时立即执行
   - 未来版本：可以通过 Celery 定时任务实现真正的延迟执行

## 注意事项

1. **循环依赖**：系统会自动检测并阻止循环依赖的配置，但建议在设计工作流时避免复杂的循环

2. **任务分配**：目标任务会根据 `PROJECT_TASK_DEFINITIONS` 中的 `assigned_role` 自动分配给对应角色的人员

3. **向后兼容**：如果数据库中没有配置，系统会自动使用硬编码配置，确保现有功能不受影响

4. **配置优先级**：数据库配置优先于硬编码配置，建议逐步将硬编码配置迁移到数据库

## 常见问题

### Q: 如何临时禁用某个转交规则？

A: 在配置列表页，取消勾选"是否启用"字段，或使用批量操作"禁用选中的转交规则"。

### Q: 如何配置多个转交目标？

A: 为同一源任务创建多条配置，通过"执行顺序"字段控制执行顺序。

### Q: 如何查看工作流的完整路径？

A: 在配置详情页的"工作流预览"字段中可以看到完整的转交路径。

### Q: 配置后为什么没有生效？

A: 检查以下几点：
1. 配置是否已启用（`is_active=True`）
2. 执行条件是否匹配（任务完成状态）
3. 源任务类型是否正确
4. 查看系统日志确认是否有错误信息

## 技术实现

- **数据模型**：`TaskAutoTransferConfig`
- **管理界面**：Django Admin
- **核心逻辑**：`views_pages.py` 中的 `_handle_task_followups` 函数
- **数据迁移**：`management/commands/init_task_transfer_configs.py`
