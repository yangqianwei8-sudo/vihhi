# 发文跟踪模块定时任务配置示例
# 使用方法：将以下内容添加到系统的 crontab 中
# 编辑 crontab: crontab -e
# 查看 crontab: crontab -l

# 注意：请根据实际项目路径和虚拟环境路径修改以下配置

# ============================================
# 发文跟踪模块定时任务
# ============================================

# 每30分钟自动更新发文跟踪状态（快递、邮件等）
# 执行时间：每30分钟的第0分钟和第30分钟
*/30 * * * * cd /home/devbox/project/vihhi/weihai_tech_production_system && source venv/bin/activate && python manage.py update_tracking_status --limit 50 >> /var/log/delivery_tracking.log 2>&1

# 或者每小时执行一次（更轻量）
# 执行时间：每小时的第0分钟
# 0 * * * * cd /home/devbox/project/vihhi/weihai_tech_production_system && source venv/bin/activate && python manage.py update_tracking_status --limit 100 >> /var/log/delivery_tracking.log 2>&1

# ============================================
# 配置说明
# ============================================

# 1. 项目路径
#    将 /home/devbox/project/vihhi/weihai_tech_production_system 替换为实际项目路径

# 2. Python虚拟环境路径
#    如果使用 source venv/bin/activate，确保 venv 目录在项目根目录下
#    或者直接使用虚拟环境的Python路径：
#    /home/devbox/project/vihhi/weihai_tech_production_system/venv/bin/python

# 3. 日志文件路径
#    将 /var/log/delivery_tracking.log 替换为实际日志文件路径
#    确保有写入权限，或者使用项目目录下的日志文件：
#    >> /home/devbox/project/vihhi/weihai_tech_production_system/logs/delivery_tracking.log 2>&1

# 4. 参数说明
#    --limit 50: 每次最多更新50条记录（避免一次处理过多数据）
#    可以根据实际情况调整，建议范围：30-100

# 5. 测试命令（手动执行测试）
