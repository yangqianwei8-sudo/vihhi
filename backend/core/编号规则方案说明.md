# 统一编号规则方案说明

## 一、方案概述

为了统一管理系统的编号生成规则，提高代码的可维护性和扩展性，我们创建了一个统一的编号生成服务。该服务支持多种编号格式和序列号策略，确保编号的唯一性和并发安全。

## 二、系统现状分析

### 2.1 现有编号类型

经过分析，系统中存在以下编号类型：

| 编号类型 | 当前格式 | 序列号策略 | 示例 |
|---------|---------|-----------|------|
| 交付单号 | VIH-JF-YYYYMMDD-0001 | 按日重置 | VIH-JF-20250101-0001 |
| 收文编号 | SWYYYY0001 | 按年重置 | SW20250001 |
| 发文编号 | FWYYYY0001 | 按年重置 | FW20250001 |
| 结算单号 | VIH-JS-项目编号-0001 | 按项目分组 | VIH-JS-PROJ001-0001 |
| 审批实例编号 | {workflow_code}-YYYYMMDD-0001 | 按日重置 | WF001-20250101-0001 |
| 客户编号 | KH-YYYYMMDD-0001 | 全局累计 | KH-20250101-0001 |
| 商机编号 | SJ-YYYYMMDD-0000 | 按日重置 | SJ-20250101-0001 |
| 项目编号 | YYYYMMDD-0000 | 按日重置 | 20250101-0001 |
| 合同编号 | HT-项目编号 | 关联项目 | HT-20250101-0001 |
| 委托书编号 | VIH-AUTH-YYYY-0001 | 按年重置 | VIH-AUTH-2025-0001 |

### 2.2 现有问题

1. **代码重复**：每个模块都有自己的编号生成逻辑，代码重复度高
2. **维护困难**：修改编号规则需要修改多处代码
3. **格式不统一**：不同模块的编号格式差异较大
4. **并发安全**：部分实现可能存在并发安全问题
5. **扩展性差**：新增编号类型需要重新实现逻辑

## 三、解决方案设计

### 3.1 核心组件

#### 1. NumberGeneratorService（编号生成服务）

**位置**：`backend/core/number_generator.py`

**功能**：
- 统一的编号生成接口
- 支持多种编号格式
- 支持多种序列号策略
- 确保并发安全
- 自动处理编号冲突

**主要方法**：
```python
NumberGeneratorService.generate(
    model_class=ModelClass,
    field_name='number_field',
    prefix='PREFIX',
    date_format='%Y%m%d',
    seq_strategy='daily',
    seq_length=4
)
```

#### 2. NumberRule（编号规则模型）

**位置**：`backend/core/number_rule_models.py`

**功能**：
- 在数据库中存储编号规则配置
- 支持动态配置和调整
- 提供规则管理界面（可选）

**主要字段**：
- `code`: 规则代码（唯一标识）
- `name`: 规则名称
- `prefix`: 编号前缀
- `date_format`: 日期格式
- `seq_strategy`: 序列号策略
- `model_app`: 应用名称
- `model_name`: 模型名称
- `field_name`: 字段名称

### 3.2 支持的编号格式

1. **前缀 + 日期 + 序列号**
   - 格式：`{prefix}-{date}-{seq}`
   - 示例：`VIH-JF-20250101-0001`

2. **前缀 + 日期**
   - 格式：`{prefix}-{date}`
   - 示例：`VIH-DATE-20250101`

3. **前缀 + 序列号**
   - 格式：`{prefix}-{seq}`
   - 示例：`PREFIX-0001`

4. **前缀 + 关联对象编号 + 序列号**
   - 格式：`{prefix}-{related_number}-{seq}`
   - 示例：`VIH-JS-PROJ001-0001`

5. **自定义模板**
   - 格式：通过模板字符串定义
   - 示例：`{prefix}-{year}-{month}-{day}-{seq_formatted}`

### 3.3 支持的序列号策略

1. **daily（按日重置）**
   - 每天从1开始计数
   - 适用于：交付单号、审批实例编号等

2. **monthly（按月重置）**
   - 每月从1开始计数
   - 适用于：月度报表编号等

3. **yearly（按年重置）**
   - 每年从1开始计数
   - 适用于：收文编号、发文编号等

4. **global（全局累计）**
   - 永不重置，全局累计
   - 适用于：客户编号等需要全局唯一的情况

5. **related（按关联对象分组）**
   - 按关联对象分组累计
   - 适用于：结算单号（按项目分组）等

## 五、使用示例

### 5.1 基础使用

```python
from backend.core.number_generator import NumberGeneratorService
from backend.apps.delivery_customer.models import DeliveryRecord

# 生成交付单号
delivery_number = NumberGeneratorService.generate(
    model_class=DeliveryRecord,
    field_name='delivery_number',
    prefix='VIH-JF',
    date_format='%Y%m%d',
    seq_strategy='daily',
    seq_length=4
)
```

### 5.2 使用便捷方法

```python
from backend.core.number_generator import generate_delivery_number

# 在模型中使用
class DeliveryRecord(models.Model):
    delivery_number = models.CharField(max_length=50, unique=True)
    
    def save(self, *args, **kwargs):
        if not self.delivery_number:
            self.delivery_number = generate_delivery_number(DeliveryRecord)
        super().save(*args, **kwargs)
```

### 5.3 使用自定义模板

```python
# 自定义格式：CUSTOM-2025-01-01-0001
custom_number = NumberGeneratorService.generate(
    model_class=YourModel,
    field_name='custom_number',
    prefix='CUSTOM',
    date_format='%Y-%m-%d',
    seq_strategy='daily',
    seq_length=4,
    template='{prefix}-{year}-{month}-{day}-{seq_formatted}'
)
```

## 六、编号规则配置建议

### 6.1 编号格式规范

建议统一使用以下格式：

1. **业务单据类**：`{业务前缀}-{日期}-{序列号}`
   - 示例：`VIH-JF-20250101-0001`（交付单）

2. **文档类**：`{文档前缀}{年份}{序列号}`
   - 示例：`SW20250001`（收文）、`FW20250001`（发文）

3. **关联类**：`{业务前缀}-{关联编号}-{序列号}`
   - 示例：`VIH-JS-PROJ001-0001`（结算单）

4. **审批类**：`{流程代码}-{日期}-{序列号}`
   - 示例：`WF001-20250101-0001`（审批实例）

### 6.2 序列号长度建议

- **高频业务**（每天>100条）：4位（0001-9999）
- **中频业务**（每天10-100条）：3位（001-999）
- **低频业务**（每天<10条）：2位（01-99）

### 6.3 序列号策略选择

- **按日重置**：适用于日常业务单据，便于按日统计
- **按年重置**：适用于年度文档编号，便于归档管理
- **全局累计**：适用于需要全局唯一性的编号
- **按关联分组**：适用于与特定对象关联的编号
