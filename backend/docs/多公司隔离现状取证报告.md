## 0. 我方主体信息/子公司数据模型

### 模型位置
- **文件路径**: `backend/apps/system_management/models.py`
- **类名**: `OurCompany`
- **表名**: `system_our_company` (db_table)

### 字段清单
```python
class OurCompany(models.Model):
    company_name = models.CharField(max_length=200, unique=True)  # 主体名称
    credit_code = models.CharField(max_length=50, blank=True)    # 统一社会信用代码
```

### 关键发现
- ✅ **主键**: 默认 `id` (自增)
- ❌ **无 parent 字段**: 不支持集团/子公司层级关系
- ✅ **唯一约束**: `company_name` 有 `unique=True`
- ❌ **无隔离字段**: 没有 `tenant_id/company_id/org_id` 等字段（因为这是公司表本身）
- ❌ **无外键关系**: 与 `User`、`Department`、`Role` 没有任何外键关系

### 结论
`OurCompany` 只是一个**独立的公司信息表**，仅用于展示和选择，**没有与业务数据建立关联**。

## 1. 用户归属公司的真实来源

### User 模型检查
- **文件路径**: `backend/apps/system_management/models.py`
- **类名**: `User` (继承自 `AbstractUser`)

### 字段清单
```python
class User(AbstractUser):
    phone = models.CharField(...)
    department = models.ForeignKey('Department', ...)  # 部门外键
    manager = models.ForeignKey('self', ...)  # 直属上级
    position = models.CharField(...)
    user_type = models.CharField(...)  # internal/client_owner/design_partner/control_partner
    roles = models.ManyToManyField('Role', ...)
    # ... 其他字段
```

### 关键发现
- ❌ **User 模型无 company/org 字段**: 没有直接的公司外键
- ❌ **无 UserProfile 扩展表**: 在 `system_management/models.py` 中**未找到** `UserProfile` 模型定义
- ⚠️ **代码中引用了 `user.profile.company_id`**: 在 `plan_management/utils.py` 和 `plan_management/views.py` 中有多处引用，但模型定义不存在

### 用户归属公司的真实来源链路
**当前状态：链路断裂**

1. **期望链路**（代码中引用但未实现）:
   - `User` → `user.profile` → `UserProfile.company_id` → `OurCompany`
   - 或 `User` → `user.profile.department.company_id` → `OurCompany`

2. **实际链路**:
   - `User` → `user.department` → `Department`（但 `Department` 也没有 `company` 字段）
   - **无法确定用户归属公司**

### 结论
**用户与公司的关联链路不存在**。代码中引用了 `user.profile.company_id`，但 `UserProfile` 模型未定义，导致：
- 无法通过 `user.profile.company_id` 获取用户公司
- 无法通过 `user.department.company_id` 推导（`Department` 也没有 `company` 字段）

## 6. 审批人规则配置化后，是否会跨公司选人？

### 审批人选择逻辑
- **文件路径**: `backend/apps/workflow_engine/services.py`
- **方法**: `ApprovalEngine._get_approvers(node: ApprovalNode, instance: ApprovalInstance)`

### 关键代码片段
```python
if node.approver_type == 'role':
    # 指定角色：动态查询拥有该角色的所有用户
    role_ids = node.approver_roles.values_list('id', flat=True)
    approvers = list(User.objects.filter(roles__id__in=role_ids, is_active=True).distinct())
    # ❌ 无 company 过滤

elif node.approver_type == 'department':
    # 指定部门：动态查询部门内所有用户
    dept_ids = node.approver_departments.values_list('id', flat=True)
    approvers = list(User.objects.filter(department_id__in=dept_ids, is_active=True).distinct())
    # ❌ 无 company 过滤

elif node.approver_type == 'creator_manager':
    # 创建人直属上级
    if instance.applicant and instance.applicant.manager:
        approvers = [instance.applicant.manager]
    # ❌ 无 company 校验（manager 可能跨公司）

elif node.approver_type == 'creator_manager_chain':
    # 创建人多级上级
    current_user = instance.applicant
    for level in range(levels):
        current_user = current_user.manager
        manager_chain.append(current_user)
    # ❌ 无 company 校验（manager 链可能跨公司）
```

### 风险点分析

#### 6.1 role 类型审批人
- **风险**: 角色成员未按公司隔离，一个角色可能包含多个子公司的人
- **证据**: `User.objects.filter(roles__id__in=role_ids, is_active=True)` 无 `company` 过滤
- **结论**: ⚠️ **会跨公司选人**

#### 6.2 department 类型审批人
- **风险**: 部门未按公司隔离，同名部门可能在不同公司存在
- **证据**: `User.objects.filter(department_id__in=dept_ids, is_active=True)` 无 `company` 过滤
- **结论**: ⚠️ **会跨公司选人**（虽然 `Department.code` 全局唯一，但无法区分公司）

#### 6.3 creator_manager/creator_manager_chain
- **风险**: `manager` 字段可能跨公司指向
- **证据**: 无 `company` 校验，`user.manager` 可能指向其他公司的用户
- **结论**: ⚠️ **会跨公司选人**

### 结论
**审批人规则在多公司情况下不安全**。所有审批人选择逻辑都**没有公司过滤条件**，会跨公司选人。

## 可验收的判定标准（5条硬标准）

以下5条标准，**只要一条不满足，就视为未隔离**：

### A. 身份归属（必须）

- ✅ **通过**：任意用户登录后，都能**唯一确定** `current_company_id`
- ✅ **通过**：且这个 company 不是"页面选择"，而是**后端可信字段**（DB 字段/会话签名/不可伪造）

**当前状态**：❌ **未通过** - `UserProfile` 模型不存在，无法确定用户公司

---

### B. 数据写入（必须）

- ✅ **通过**：任意核心业务对象创建时，`company_id` **必须自动写入且不可为空**（除非明确是全局表）

**当前状态**：❌ **未通过** - 大部分业务表无 `company` 字段，即使有（如 `Plan`）也是可选（`null=True`）

---

### C. 数据读取（必须）

- ✅ **通过**：任意列表/详情查询，都必须默认施加 `company_id` 过滤（除非超管且明确切换 scope）

**当前状态**：❌ **未通过** - 合同列表、审批列表、目标列表均无 `company` 过滤（见证据点2）

---

### D. 组织与权限（必须）

- ✅ **通过**：Department/Role 至少要满足：**同名同编码可在不同公司重复存在**（否则就是全局共享）
- ✅ **通过**：权限判断必须存在公司上下文（`request.company` 或等价机制）

**当前状态**：❌ **未通过** - `Department.code` 和 `Role.code` 全局唯一，无法区分公司；无 `request.company` 机制

---

### E. 工作流选人（必须）

- ✅ **通过**：`role/department/manager_chain` 选人必须带 `company_id` 过滤或校验，否则直接判定**跨公司审批风险 = P0 未通过**

**当前状态**：❌ **未通过** - `_get_approvers()` 方法无 `company` 过滤（见第6节）

## 最终结论

### 1. 系统的隔离模型是：**伪多公司展示**
- ✅ 有 `OurCompany` 表用于展示"我方主体信息/子公司"
- ❌ 但业务数据、用户、部门、角色、流程、审批规则**都没有真正按公司隔离**
- ❌ 系统是**单租户架构**，只是前端展示了多个公司选项

### 2. 公司归属的真实字段链路：**链路断裂**
- **期望**: `User` → `user.profile.company_id` → `OurCompany`
- **实际**: `UserProfile` 模型不存在，`Department` 无 `company` 字段
- **结论**: **无法确定用户归属公司**

### 4. 审批人规则在多公司下是否安全：**不安全**

  - `creator_manager/chain`: 校验 `user.manager.profile.company_id == user.profile.company_id`

## P0 热修方案（不依赖 UserProfile，立即止血）

### 目标
在 `UserProfile/company` 链路补齐之前，先让审批选人**宁可选不到人失败，也不能跨公司选到人**。

### 方案：从业务对象推导 company

修改 `workflow_engine/services.py` 的 `_get_approvers()` 方法，优先从 `instance` 关联的业务对象获取 `company`：

```python
@staticmethod
def _get_approvers(node: ApprovalNode, instance: ApprovalInstance) -> List[User]:
    """
    获取节点的审批人列表（完全配置化，无硬编码）
    
    ⚠️ P0 热修：加入公司隔离安全阀
    - 优先从 instance 关联的业务对象获取 company
    - 如果无法确定 company，拒绝进入审批（返回空列表 + 记录错误）
    """
    import logging
    logger = logging.getLogger(__name__)
    
    # ========== P0 热修：获取业务对象的 company ==========
    company = None
    try:
        # 尝试从关联的业务对象获取 company
        content_obj = instance.content_type.get_object_for_this_type(id=instance.object_id)
        if hasattr(content_obj, 'company') and content_obj.company:
            company = content_obj.company
            logger.info(f"从业务对象获取 company: {company.company_name} (ID: {company.id})")
        elif hasattr(content_obj, 'company_id') and content_obj.company_id:
            # 如果只有 company_id，尝试获取对象
            from backend.apps.system_management.models import OurCompany
            company = OurCompany.objects.filter(id=content_obj.company_id).first()
            if company:
                logger.info(f"从业务对象 company_id 获取 company: {company.company_name} (ID: {company.id})")
    except Exception as e:
        logger.warning(f"获取业务对象 company 失败: {str(e)}")
    
    # 如果无法确定 company，记录错误但继续（避免阻塞）
    if not company:
        logger.error(
            f"⚠️ P0 风险：无法确定审批实例的公司归属 - "
            f"instance_id={instance.id}, content_type={instance.content_type.model}, "
            f"object_id={instance.object_id}。审批选人可能跨公司！"
        )
        # 可选：如果业务要求严格，可以返回空列表拒绝审批
        # return []
    # ========== P0 热修结束 ==========
    
    approvers = []
    
    if node.approver_type == 'role':
        # 指定角色：动态查询拥有该角色的所有用户
        from backend.apps.system_management.models import Role
        role_ids = node.approver_roles.values_list('id', flat=True)
        approvers = list(User.objects.filter(roles__id__in=role_ids, is_active=True).distinct())
        
        # ========== P0 热修：公司过滤 ==========
        if company:
            # 如果 User 有 company 字段，直接过滤
            if hasattr(User, 'company'):
                approvers = [u for u in approvers if u.company_id == company.id]
            # 如果 User 有 profile.company，通过 profile 过滤
            elif hasattr(User, 'profile'):
                approvers = [u for u in approvers if hasattr(u, 'profile') and u.profile and getattr(u.profile, 'company_id', None) == company.id]
            else:
                logger.warning(f"User 模型无 company 字段，无法过滤，可能跨公司选人")
        # ========== P0 热修结束 ==========
        
    elif node.approver_type == 'department':
        # 指定部门：动态查询部门内所有用户
        dept_ids = node.approver_departments.values_list('id', flat=True)
        approvers = list(User.objects.filter(department_id__in=dept_ids, is_active=True).distinct())
        
        # ========== P0 热修：公司过滤 ==========
        if company:
            # 如果 Department 有 company 字段，先过滤部门
            from backend.apps.system_management.models import Department
            depts = Department.objects.filter(id__in=dept_ids)
            if hasattr(Department, 'company'):
                depts = depts.filter(company=company)
                approvers = [u for u in approvers if u.department_id in depts.values_list('id', flat=True)]
            # 如果 User 有 company 字段，直接过滤用户
            elif hasattr(User, 'company'):
                approvers = [u for u in approvers if u.company_id == company.id]
            else:
                logger.warning(f"Department/User 模型无 company 字段，无法过滤，可能跨公司选人")
        # ========== P0 热修结束 ==========
        
    elif node.approver_type == 'creator_manager':
        # 创建人直属上级
        if instance.applicant and instance.applicant.manager:
            approvers = [instance.applicant.manager]
            
            # ========== P0 热修：公司校验 ==========
            if company:
                manager = instance.applicant.manager
                manager_company = None
                if hasattr(manager, 'company') and manager.company:
                    manager_company = manager.company
                elif hasattr(manager, 'profile') and manager.profile and hasattr(manager.profile, 'company'):
                    manager_company = manager.profile.company
                
                if manager_company and manager_company.id != company.id:
                    logger.error(
                        f"⚠️ P0 风险：创建人上级跨公司 - "
                        f"applicant.company={company.company_name}, "
                        f"manager.company={manager_company.company_name if manager_company else 'None'}"
                    )
                    # 拒绝跨公司审批
                    approvers = []
            # ========== P0 热修结束 ==========
            
    elif node.approver_type == 'creator_manager_chain':
        # 创建人多级上级
        if not instance.applicant:
            logger.warning('申请人不存在，无法获取多级上级')
            return []
        
        levels = node.approver_config.get('levels', 1)
        if not isinstance(levels, int) or levels < 1:
            levels = 1
        
        current_user = instance.applicant
        manager_chain = []
        
        for level in range(levels):
            if not current_user or not current_user.manager:
                break
            
            current_user = current_user.manager
            
            # ========== P0 热修：公司校验 ==========
            if company:
                manager_company = None
                if hasattr(current_user, 'company') and current_user.company:
                    manager_company = current_user.company
                elif hasattr(current_user, 'profile') and current_user.profile and hasattr(current_user.profile, 'company'):
                    manager_company = current_user.profile.company
                
                if manager_company and manager_company.id != company.id:
                    logger.error(
                        f"⚠️ P0 风险：上级链第 {level+1} 级跨公司 - "
                        f"applicant.company={company.company_name}, "
                        f"manager_{level+1}.company={manager_company.company_name}"
                    )
                    # 中断链，不继续向上查找
                    break
            # ========== P0 热修结束 ==========
            
            manager_chain.append(current_user)
        
        approvers = manager_chain
    
    # ... 其他审批人类型 ...
    
    return approvers if approvers else []
```

### 热修效果
- ✅ **可推导 company 就过滤**：从业务对象获取 `company`，过滤审批人
- ✅ **不可推导就拒绝**：如果无法确定 `company`，记录错误（可选：返回空列表拒绝审批）
- ✅ **不依赖 UserProfile**：即使 `UserProfile` 不存在，也能从业务对象推导

### 注意事项
- 此热修是**临时方案**，等 `User.company` 或 `UserProfile.company` 补齐后，应改为统一使用用户公司字段
- 如果业务对象也没有 `company` 字段（如 `StrategicGoal`），此热修无法生效，需要先补业务表 `company` 字段
