## Phase 1: 最小补齐 - 已完成

### P1-1: WorkflowBinding 模型

**文件**: `backend/apps/workflow_engine/models.py`

**模型字段**:
- `content_type`: 业务对象类型（ForeignKey to ContentType）
- `action`: 操作类型（CharField，choices: submit/start/cancel/approve/reject/withdraw）
- `workflow_template`: 流程模板（ForeignKey to WorkflowTemplate）
- `priority`: 优先级（IntegerField，数字越大优先级越高）
- `is_active`: 是否启用（BooleanField）
- `note`: 备注（TextField）
- 审计字段: `created_by`, `created_time`, `updated_by`, `updated_time`

**唯一生效规则**:
- 通过 `clean()` 方法实现：同一 `content_type` + `action` + `is_active=True` 时，只能有 1 条优先级最高的配置生效
- 保存时自动验证，如果冲突会抛出 ValidationError

**迁移文件**: `backend/apps/workflow_engine/migrations/0008_add_workflow_binding.py`

### P1-2: WorkflowBindingAdmin

**文件**: `backend/apps/workflow_engine/admin.py`

**功能**:
- ✅ 列表页显示：业务对象类型、操作类型、流程模板、优先级、是否启用、创建人、创建时间
- ✅ 筛选：按 is_active、action、content_type、created_time
- ✅ 搜索：按 note、workflow_template__name、workflow_template__code
- ✅ 保存时自动记录 created_by / updated_by
- ✅ 保存时执行模型验证（包括唯一生效规则）

**访问路径**: Django Admin → `/admin/workflow_engine/workflowbinding/`

## Phase 2: 配置接入业务 - 已完成

### P2-1: LoanApplication (借款申请) 接入配置优先

**服务类**: `LoanApprovalService`  
**文件**: `backend/apps/administrative_management/services/loan_approval.py`

**实现方式**:
- `LoanApprovalService` 继承自 `UniversalApprovalService`
- `UniversalApprovalService.submit_approval()` 已修改为调用 `get_workflow(obj=obj, action='submit', use_binding=True)`
- `UniversalApprovalService.get_workflow()` 已支持"配置优先、兜底原逻辑"

**逻辑流程**:
1. 提交审批时，先尝试从 `WorkflowBinding` 配置获取流程模板
2. 如果找到配置且配置的流程模板存在，使用配置的模板
3. 如果未找到配置，兜底使用原逻辑（按 `WORKFLOW_CODE = 'loan_approval'` 查找）

## 验收测试步骤

### 测试 1: 无配置时，仍走原模板（兜底逻辑）

**前置条件**:
- 确保 `WorkflowTemplate` 中存在 `code='loan_approval'` 且 `status='active'` 的模板
- 确保 `WorkflowBinding` 中**没有** `content_type=loanapplication` + `action=submit` 的启用配置

**测试步骤**:
1. 创建一个 `LoanApplication` 对象
2. 调用 `LoanApprovalService().submit_approval(loan_obj, applicant=user)`
3. 检查生成的 `ApprovalInstance.workflow.code` 是否为 `'loan_approval'`

**预期结果**:
- ✅ 审批实例创建成功
- ✅ `ApprovalInstance.workflow.code == 'loan_approval'`
- ✅ 日志中显示：`'审批流程模板不存在: loan_approval'` 或正常创建实例

**验收证据**:
```python
# 在 Django shell 中执行
from backend.apps.administrative_management.models import LoanApplication
from backend.apps.administrative_management.services.loan_approval import LoanApprovalService
from backend.apps.workflow_engine.models import WorkflowBinding
from django.contrib.contenttypes.models import ContentType

# 1. 确认无绑定配置
content_type = ContentType.objects.get_for_model(LoanApplication)
binding = WorkflowBinding.objects.filter(
    content_type=content_type,
    action='submit',
    is_active=True
).first()
assert binding is None, "应该没有绑定配置"

# 2. 创建借款申请并提交审批
loan = LoanApplication.objects.first()  # 或创建一个新的
service = LoanApprovalService()
instance = service.submit_approval(loan, applicant=user, comment='测试无配置')

# 3. 验证使用原模板
assert instance is not None, "审批实例应该创建成功"
assert instance.workflow.code == 'loan_approval', f"应该使用原模板，实际: {instance.workflow.code}"
```

### 测试 2: 有配置时，走配置模板

**前置条件**:
- 确保 `WorkflowTemplate` 中存在另一个模板（例如 `code='loan_approval_v2'` 且 `status='active'`）
- 在 `WorkflowBinding` 中创建配置：`content_type=loanapplication` + `action=submit` → `workflow_template=loan_approval_v2`

**测试步骤**:
1. 在 Django Admin 中创建 `WorkflowBinding` 配置：
   - 业务对象类型: `loanapplication`
   - 操作类型: `submit`
   - 流程模板: `loan_approval_v2`（或其他模板）
   - 优先级: `10`
   - 是否启用: `True`
2. 创建一个 `LoanApplication` 对象
3. 调用 `LoanApprovalService().submit_approval(loan_obj, applicant=user)`
4. 检查生成的 `ApprovalInstance.workflow.code` 是否为配置的模板代码

**预期结果**:
- ✅ 审批实例创建成功
- ✅ `ApprovalInstance.workflow.code == 'loan_approval_v2'`（或配置的模板代码）
- ✅ 日志中显示：`'从绑定配置获取流程模板: loan_approval_v2 (绑定ID: X)'`

**验收证据**:
```python
# 在 Django shell 中执行
from backend.apps.administrative_management.models import LoanApplication
from backend.apps.administrative_management.services.loan_approval import LoanApprovalService
from backend.apps.workflow_engine.models import WorkflowBinding, WorkflowTemplate
from django.contrib.contenttypes.models import ContentType

# 1. 创建或获取配置的模板
workflow_v2 = WorkflowTemplate.objects.get(code='loan_approval_v2', status='active')

# 2. 创建绑定配置
content_type = ContentType.objects.get_for_model(LoanApplication)
binding = WorkflowBinding.objects.create(
    content_type=content_type,
    action='submit',
    workflow_template=workflow_v2,
    priority=10,
    is_active=True,
    created_by=user,
    note='测试配置优先'
)

# 3. 创建借款申请并提交审批
loan = LoanApplication.objects.first()  # 或创建一个新的
service = LoanApprovalService()
instance = service.submit_approval(loan, applicant=user, comment='测试有配置')

# 4. 验证使用配置模板
assert instance is not None, "审批实例应该创建成功"
assert instance.workflow.code == 'loan_approval_v2', f"应该使用配置模板，实际: {instance.workflow.code}"

# 5. 清理测试数据（可选）
binding.delete()
```

### 测试 3: 历史实例不变，新实例按配置

**前置条件**:
- 已有历史审批实例（使用原模板 `loan_approval`）
- 已创建新的绑定配置（指向 `loan_approval_v2`）

**测试步骤**:
1. 查询历史审批实例，确认使用原模板
2. 创建新的审批实例，确认使用配置模板

**预期结果**:
- ✅ 历史实例的 `workflow.code` 仍为 `'loan_approval'`
- ✅ 新实例的 `workflow.code` 为配置的模板代码（如 `'loan_approval_v2'`）

**验收证据**:
```python
# 在 Django shell 中执行
from backend.apps.workflow_engine.models import ApprovalInstance
from django.contrib.contenttypes.models import ContentType

# 1. 查询历史实例（在创建配置之前创建的）
content_type = ContentType.objects.get_for_model(LoanApplication)
old_instances = ApprovalInstance.objects.filter(
    content_type=content_type,
    workflow__code='loan_approval'
).order_by('-created_time')[:5]

print("历史实例（使用原模板）:")
for instance in old_instances:
    print(f"  - {instance.instance_number}: {instance.workflow.code}")

# 2. 查询新实例（在创建配置之后创建的）
new_instances = ApprovalInstance.objects.filter(
    content_type=content_type,
    workflow__code='loan_approval_v2'
).order_by('-created_time')[:5]

print("新实例（使用配置模板）:")
for instance in new_instances:
    print(f"  - {instance.instance_number}: {instance.workflow.code}")
```
